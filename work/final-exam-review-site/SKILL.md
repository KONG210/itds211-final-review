# Final exam review site

สร้างชุดทบทวนสอบและเว็บไซต์จากเอกสารของผู้ใช้เท่านั้น ใช้ภาษาที่ผู้ใช้เลือก; หากผู้ใช้เขียนภาษาไทย ให้เขียนไทยที่อ่านง่ายและคงศัพท์เทคนิค สูตร สัญลักษณ์ ชื่อทฤษฎี และคำนิยามตามต้นฉบับ

## ข้อมูลตั้งต้น

ก่อนเริ่มอ่านเพื่อสรุป ให้ตรวจว่าทราบข้อมูลต่อไปนี้หรือยัง และถามเฉพาะข้อที่ยังขาด:

1. วิชาและชื่ออาจารย์หรือรหัสวิชา
2. บทหรือหัวข้อที่อยู่ในขอบเขตสอบ
3. รูปแบบข้อสอบ เช่น เลือกตอบ อัตนัย คำนวณ หรือวิเคราะห์
4. จำนวนวันที่เหลือและวันสอบ
5. เอกสารที่ให้ใช้ เช่น สไลด์ แบบฝึกหัด ข้อสอบเก่า หรือโน้ต
6. โทนสีหรือสไตล์เว็บที่ต้องการ

หากยังไม่มีเอกสาร หยุดการสร้างเนื้อหาวิชาและขอเอกสารก่อน ข้อมูลข้อ 1, 3, 4 หรือ 6 ที่ไม่ทราบไม่ควรถูกเดา; หากผู้ใช้ยังตอบไม่ได้ ให้ใช้ค่าเป็น “ไม่ระบุ” และปรับส่วนที่ขึ้นกับข้อมูลนั้นให้เป็นแผนทั่วไปอย่างชัดเจน

## แหล่งข้อมูลและความถูกต้อง

- อ่านทุกไฟล์ที่ผู้ใช้ให้ก่อนจัดโครงสร้างเนื้อหา สำหรับ PDF หรือสไลด์ ให้ตรวจหน้าที่มีแผนภาพ ตาราง สมการ และข้อความในภาพด้วย ตรวจและแจ้งหน้าที่อ่านไม่ได้หรือคลุมเครือ
- ใช้เอกสารที่ให้เป็นแหล่งเดียวของเนื้อหาวิชา ห้ามเติมข้อเท็จจริง ทฤษฎี สูตร ขั้นตอน หรือเฉลยจากความรู้ภายนอก คำอธิบายที่ย่อใหม่ต้องรักษาเงื่อนไขและความหมายเดิม ไม่คัดลอกข้อความยาว
- ทำแผนที่บทและหัวข้อพร้อมตำแหน่งต้นฉบับก่อนเขียนสรุป ทุกหัวข้อและภาพต้องอ้างชื่อไฟล์กับหน้า สไลด์ หรือหัวข้อ เช่น `Slide_Ch4.pdf, สไลด์ 8` หากเลขหน้าที่พิมพ์บนสไลด์ต่างจากลำดับหน้า PDF ให้ระบุทั้งคู่เมื่อจำเป็น ห้ามประดิษฐ์เลขหน้า
- สำหรับข้อมูลที่ไม่พบ อ่านไม่ชัด หรือแหล่งข้อมูลขัดกัน ให้เขียน “ต้องตรวจสอบจากต้นฉบับ” พร้อมระบุจุดที่มีปัญหา อย่าสร้างคำตอบทดแทน
- ใช้วัตถุประสงค์การเรียนรู้ ความถี่/น้ำหนักในเอกสาร แบบฝึกหัด และข้อสอบเก่าที่ผู้ใช้ให้ เพื่อประเมินความสำคัญ หากไม่มีหลักฐานเรื่องแนวข้อสอบ ให้เรียกระดับความสำคัญว่าเป็น “การประเมินเพื่อจัดเวลาอ่าน” ไม่ยืนยันว่าจะออกสอบ

## ชุดทบทวนก่อนสร้างเว็บ

จัดทำและแสดงผลตามลำดับนี้ก่อนลงมือสร้างเว็บไซต์ โดยใช้รายละเอียดตามปริมาณและความยากของเอกสาร:

เปิดแต่ละบทด้วย **“บทนี้เรียนเพื่ออะไร”** และ **“จุดประสงค์ของบทนี้”** พร้อมตำแหน่งอ้างอิง อธิบายว่าบทนั้นช่วยให้เข้าใจหรือทำอะไรได้ตามหลักฐานในเอกสาร แยกวัตถุประสงค์รายวิชาออกจากวัตถุประสงค์รายบท หากต้นฉบับไม่ได้ระบุจุดประสงค์ของบทโดยตรง ให้ระบุว่าเป็น “สรุปเป้าหมายจากเนื้อหา” และเขียน “วัตถุประสงค์รายบทที่ระบุโดยตรง: ต้องตรวจสอบจากต้นฉบับ” ห้ามเติมเป้าหมายที่เอกสารไม่รองรับ ให้ส่วนนี้ปรากฏทั้งในสรุปและหน้าเว็บของแต่ละบท

1. **ภาพรวมเนื้อหาและระดับความสำคัญ:** จำนวนบท/หัวข้อและแผนผังหัวข้อ; กำหนด 🔴 ต้องจำแน่นอน สำหรับนิยาม หลักการ สูตร กฎ ทฤษฎี ขั้นตอน หรือแนวคิดหลัก, 🟡 สำคัญ สำหรับตัวอย่าง การเปรียบเทียบ และการประยุกต์, ⚪ อ่านเสริม สำหรับรายละเอียดประกอบ อธิบายเหตุผลของการจัดระดับเมื่อไม่ชัด
2. **สรุปรายบท:** ทุกหัวข้อมีชื่อ ตำแหน่งต้นฉบับ ระดับความสำคัญ ใจความสำคัญ 2–4 ประโยค ประเด็นที่ต้องจำ ศัพท์/สูตร/สัญลักษณ์/นิยามที่มีในต้นฉบับ ตัวอย่างหรือวิธีคิดที่มี การเปรียบเทียบเมื่อช่วยแยกความต่าง จุดที่อาจสับสน และประโยคช่วยจำเมื่อมีรายละเอียดมาก อย่ากรอกข้อมูลที่เอกสารไม่มี; ใช้คำว่า “ต้องตรวจสอบจากต้นฉบับ” สำหรับข้อมูลที่ขาดหรือไม่ชัด
3. **Roadmap ทบทวน:** เรียงหัวข้อที่เป็นพื้นฐานก่อนหัวข้อที่ต้องใช้ความรู้ก่อนหน้า และอ้างตำแหน่งต้นฉบับของแต่ละช่วง
4. **แผนทบทวนตามเวลา:** ผูกหัวข้อกับจำนวนวันและวันสอบที่ผู้ใช้ให้ พร้อมช่วงทำแบบฝึกตอบและทวนจุดที่ผิด หากไม่ทราบเวลา ให้เสนอแผน 3 วัน, 1 วัน และ 3 ชั่วโมงโดยระบุว่าเป็นตัวเลือกทั่วไป
5. **ชุดคำถามฝึกตอบและกลยุทธ์สอบ:** ทำคำถามทำนาย 3 ข้อต่อหัวข้อพร้อมเฉลยสั้นและตำแหน่งอ้างอิง คำถามทุกข้อและคำตอบต้องตอบได้จากเอกสาร แยกสิ่งที่ควรท่องจำ ฝึกโจทย์ หรือเข้าใจแนวคิด เสนอแนวเลือกตอบ อัตนัย คำนวณ หรือวิเคราะห์ตามรูปแบบสอบที่ทราบ พร้อมลำดับอ่านเมื่อเหลือ 3 วัน, 1 วัน และ 3 ชั่วโมง เรียกคำถามเหล่านี้ว่าแบบฝึกจากเอกสาร ไม่อ้างว่าเป็นข้อสอบจริง

หากหัวข้อใดมีข้อมูลไม่พอสำหรับคำถาม 3 ข้อ ให้บอกข้อจำกัดแทนการแต่งเนื้อหาใหม่ ตัวอย่างสมมติใช้ได้เฉพาะเมื่อผู้ใช้อนุญาตและต้องติดป้ายว่าเป็นตัวอย่างที่สร้างขึ้น ไม่ใช่ข้อความจากต้นฉบับ

## เว็บไซต์ทบทวนออฟไลน์

หลังแสดงชุดทบทวน ให้สร้างเว็บไซต์ที่ใช้ HTML, CSS และ JavaScript อยู่ในไฟล์ HTML เดียว โดยไม่ใช้เครือข่าย ไลบรารีภายนอก หรือระบบล็อกอิน ใช้ได้บนมือถือและคอมพิวเตอร์

- หน้าแรกแสดงจำนวนบท จำนวนหัวข้อ สัดส่วน 🔴/🟡/⚪ และความคืบหน้าที่ทบทวนแล้ว
- มีเมนูไปแต่ละบท/หัวข้อ ค้นหาหัวข้อ ข้อความ ศัพท์ สูตร และคำอธิบายรูป; แสดงระดับด้วยป้ายสีแดง เหลือง เทา พร้อมข้อความกำกับ ไม่พึ่งสีอย่างเดียว
- ทุกหัวข้อแสดงชื่อไฟล์และตำแหน่งหน้า/สไลด์ชัดเจน มีเช็กลิสต์ทบทวนที่บันทึกใน `localStorage`, ตัวนับ เช่น `7/25 หัวข้อ`, โหมดทบทวนด่วนเฉพาะ 🔴 และ Dark Mode
- โหมดทดสอบตัวเองสุ่มจากทุกหัวข้อที่มีคำถาม และซ่อนเฉลยจนผู้ใช้กดดู; Flashcard ใช้เฉพาะศัพท์ นิยาม และสูตรที่พบในเอกสาร
- เมื่อเอกสารมีภาพสำคัญ ให้ดึงภาพที่จำเป็นมาไว้ในโฟลเดอร์ `images` ข้างไฟล์ HTML แต่ละภาพมีคำอธิบายและไฟล์/หน้าต้นทาง คลิกขยายได้ รองรับหน้าจอเล็ก มีตัวกรองหัวข้อที่มีรูป และแกลเลอรีภาพสำคัญ หากผู้ใช้ต้องการเพียงไฟล์ทางกายภาพไฟล์เดียวจริง ๆ ให้ฝังภาพลงใน HTML แทนและแจ้งผลต่อขนาดไฟล์
- ใช้ HTML ที่มีความหมาย ปุ่มที่ใช้แป้นพิมพ์ได้ จุดโฟกัสที่เห็นชัด คอนทราสต์อ่านง่าย และการจัดวางที่มีพื้นที่ว่างพอเหมาะ ข้อความจากเอกสารต้องถูกเข้ารหัสอย่างปลอดภัยก่อนใส่ใน HTML/JavaScript

## ตรวจงานก่อนส่ง

- เทียบทุกบท หัวข้อ สูตร เงื่อนไข เฉลย ภาพ และตำแหน่งอ้างอิงกับแผนที่ต้นฉบับ; เปิดเผยส่วนที่ตรวจไม่ได้
- เปิดเว็บแบบออฟไลน์ ตรวจเมนู ค้นหา ตัวกรอง เช็กลิสต์และการคงสถานะหลังรีเฟรช โหมดด่วน คำถาม/เฉลย Flashcard Dark Mode ภาพขยาย และหน้าจอมือถือ
- ส่งไฟล์ HTML และ `images` เมื่อใช้ภาพแยก พร้อมสรุปสิ่งที่มีในเว็บและข้อจำกัดของเอกสารที่ส่งผลต่อความถูกต้อง
